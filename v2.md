# 🐍 Python Code Portability & Standards (Nov 2025)

**System Instructions & Contribution Guidelines**

> **Target Runtime:** CPython 3.11–3.14  
> **Supported Platforms:** Windows, macOS, Linux  
> **Minimum Version:** Python 3.11

This document defines the standards for code portability, robustness, and modern Python practices in this workspace. It governs both AI-generated code and manual contributions.

---

## 🟢 Rules

Treat these as **always-on** instructions for code creation and refactoring.

### 1. General Behavior & Safety
*   **Preserve Behavior:** Do not change existing behavior, CLI flags, or file formats unless fixing a clear bug.
*   **Explicit Changes:** Call out any behavioral changes explicitly in your summary.
*   **Dependencies:**
    *   Do not add runtime dependencies without justification; prefer the Standard Library (3.11+).
    *   Dev/test tools (pytest, ruff, mypy) must be kept in `dev` configurations, never runtime.
*   **Runnable Code:** All examples and edits must be copy-paste-ready (no pseudo-code).

### 2. Portability Assumptions
*   **Interpreter:** Do not assume the executable is named `python`.
    *   *In code:* Use `sys.executable` with `-m`.
    *   *In docs:* Use `py -3.x` (Windows) or `python3.x` (Unix).
*   **OS Support:** Code must run unmodified on Windows, macOS, and Linux.

### 3. Paths & Filesystem
*   **Library:** Use `pathlib.Path` exclusively. Do not use `os.path`.
*   **Project Root Derivation:** Handle non-file contexts (REPL/Notebooks) safely:
    ```python
    from pathlib import Path

    if "__file__" in globals():
        BASE_DIR = Path(__file__).resolve().parent
    else:
        BASE_DIR = Path.cwd()
    ```
*   **Package Resources:** Use `importlib.resources`.
    ```python
    from importlib.resources import files
    # Use as_file() if a real filesystem path is needed (e.g., for C libraries)
    data_path = files("package_name") / "data" / "config.json"
    ```
*   **Case Sensitivity:** Always match filename case exactly.

### 4. Text I/O & Encodings
*   **Encoding:** Always specify `encoding="utf-8"` in `open()`, `read_text()`, etc.
*   **Newlines:** Use `newline=""` **only** when required by a library (e.g., `csv`). Otherwise, let Python handle platform line endings.
*   **TOML:** Use `tomllib` (stdlib) for reading. Do not add external TOML writers without justification.

### 5. Configuration & Secrets
*   **Secrets:** Use environment variables. **Never** hard-code keys/tokens.
*   **Dotenv:** `.env` files are for local convenience only. Load them only in entrypoints (CLIs), never in libraries.
*   **Validation:** Fail fast at startup if required env vars are missing.

> **💡 Windows Timezone Note:** If the project relies on IANA names (e.g., "Europe/Berlin") and must run on Windows, you **should** depend on `tzdata` to ensure `zoneinfo` can load them.

### 6. Logging
*   **No Print:** Use `logging` for diagnostics. `print()` is for CLI user output only.
*   **Applications:** Configure `logging.basicConfig` (File + Console) once in the entrypoint.
*   **Libraries:** Use module-level loggers with a NullHandler.
    ```python
    logger = logging.getLogger(__name__)
    logger.addHandler(logging.NullHandler())
    ```

### 7. Time & Dates
*   **Timezones:** Use `zoneinfo.ZoneInfo`. **Do not use `pytz`.**
*   **Current Time:** Use timezone-aware UTC.
    ```python
    from datetime import datetime, UTC
    now = datetime.now(UTC)
    ```
    ❌ **Banned:** `datetime.utcnow()`, `datetime.utcfromtimestamp()` (Deprecated).
*   **Storage:** Store internally as UTC; convert to local time only for display.

### 8. Subprocesses
*   **Execution:** Prefer `subprocess.run(..., check=True)`.
*   **Invocation:** Always invoke Python via `sys.executable`.
    ```python
    subprocess.run([sys.executable, "-m", "module_name"], check=True)
    ```
*   **Shell:** Avoid `shell=True`.
*   **Signals:** Handle `SIGINT`/`SIGTERM` gracefully. Be aware `asyncio.add_signal_handler` has limited support on Windows.

### 9. Virtual Environments
*   **Naming:** `.venv` at project root.
*   **Creation:**
    *   Windows: `py -3.11 -m venv .venv`
    *   Unix: `python3.11 -m venv .venv`
*   **Scope:** Assume all commands run inside the venv. Do not suggest global installs.

### 10. Packaging
*   **Libraries:** `pyproject.toml` with PEP 621 metadata is mandatory.
*   **Applications:** Use pinned `requirements.txt` or lockfiles (uv, poetry).
*   **Builds:** Use `python -m build`.

### 11. Testing & CI
*   **Framework:** Default to `pytest`. Use `pytest-asyncio` for async.
*   **Concurrency:** Prefer `asyncio.TaskGroup` (3.11+) for new tests.
*   **Matrix:** Assume tests run on Linux, Windows, and macOS.
*   **Headless:** Tests must not require interactive input.

### 12. Code Style & Typing
*   **Syntax:** Python 3.11+ Modern Syntax.
    *   ✅ `str | int`
    *   ✅ `list[str]`, `dict[str, int]`
    *   ❌ `typing.Union`, `typing.List`, `typing.Dict`, `typing.Optional`
*   **Allowed Typing Imports:** `Protocol`, `TypedDict`, `Literal`, `Any`, `TYPE_CHECKING` are allowed.
*   **Future Imports:** Do **not** use `from __future__ import annotations` in new code.
*   **Docstrings:** Update docstrings whenever behavior or signatures change.

### 13. Interaction
*   **No Blocking:** Do not use `input("Press Enter")`.
*   **UX:** Prefer CLI args/env vars over interactive prompts.
*   **Batch:** Use non-zero exit codes and stderr for errors.

## 🔄 Workflow

1.  **Classify & Target:** Identify if it's an App or Lib. Confirm Python 3.11+ target.
2.  **Plan:** Identify legacy patterns (`os.path`, `utcnow`, `typing.List`).
3.  **Refactor:**
    *   Switch to `pathlib`.
    *   Enforce `encoding="utf-8"`.
    *   Standardize on `datetime.now(UTC)`.
4.  **Stabilize:** Ensure behavior remains consistent. Document changes.
5.  **Test:** Add async/cross-platform tests. Update types.
6.  **Summarize:** List changes, dependencies, and migration notes.

## 📚 Knowledge Baseline (2025)

*   **Status:** Python 3.14 is stable; 3.10 is security-only. 3.11 is the floor.
*   **Typing:** Generics (`list[]`) and Unions (`|`) are standard.
*   **Async:** `asyncio.TaskGroup` is preferred over `gather` for robust error handling (using `ExceptionGroup`).
*   **Config:** `tomllib` is the standard for reading TOML.
*   **Time:** `datetime.UTC` and `zoneinfo` are the standard. `tzdata` is required for Windows portability with named zones.
